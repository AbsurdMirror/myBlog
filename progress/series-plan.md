## 1. 系列规模与组织原则

**当前规划：约 6 篇技术正文＋1 个系列目录页。**

按读者理解模型的层级分篇，不按聊天顺序、网络层数量或图片数量分篇。一篇可以包含多张图，一个模型也不必机械地凑满六篇；后续由用户指导，必要时再拆分过长章节。

DeepSeek-V4.1-Flash 是第一套系列，Layer 0 是当前基准层。以后解析其他 LLM 时复用组织方法，不照搬 DeepSeek 的层分类、模块配置或数字。

| 页面 | 建议文件名 | 核心问题 | 内容边界 |
|---|---|---|---|
| 系列目录页 | `index.md` | 这套系列讲什么，应该按什么顺序读？ | 模型身份、版本、阅读导航、来源及完成状态；不算技术正文。 |
| ① 模型全貌 | `01-overview.md` | 从外部和整体结构看，模型由什么组成？ | 输入输出、主干、层分类、缓存与状态概览，不逐算子推导。 |
| ② 基准层详解 | **`02-layer0.md`** | 一个代表层完整地怎样计算？ | 八模块数据流、mHC、RMSNorm、SWA、MoE，公式、shape、参数量。 |
| ③ 其他层的差异 | `03-layer-differences.md` | 相对基准层，其他层哪里不同？ | 新增、删除、变化和复用关系；相同模块直接引用第②篇。 |

| ⑤ 完整推理过程 | `05-inference.md` | 输入、生成和多轮对话如何串起整个模型？ | Prefill、Decode、状态更新与跨轮保留，重点是时间顺序与依赖。 |

## 2. 每一篇具体写什么

### 系列目录页：读者入口，不重复讲一遍模型

建议包含以下信息：

- **模型身份**：准确模型名、变体、本文研究范围，以及与同系列其他变体的区别。
- **版本依据**：官方资料入口、实际核对的源码 revision 或日期；候选但未验证的 revision 不能写成锁定版本。
- **阅读顺序**：六篇的名称、每篇解决的问题、前置依赖与实际可用链接。
- **完成状态**：已发布、已有草稿、仅有提纲、尚未开始；不得用空链接假装文章存在。
- **符号入口**：B、S、S_his、hidden 等约定，以及必要的共用术语说明。

目录页记录“读者需要知道的进度”；具体未解决问题和执行日志放在 `progress/`，不要堆在阅读首页。

### ① 模型全貌：先建立整张地图

建议内部顺序：

1. 研究对象、输入与输出，以及本文采用的分析口径。
2. 从输入端到输出端的整体结构：主干与外围模块的连接关系。
3. 层分类：按明确维度分类，说明各类层分布在哪里、职责是什么。
4. 层间传递的数据，以及模型需要跨 token／跨轮保存的状态。
5. 缓存组成与一个统一示例，为后续成本分析建立概念。
6. 全系列阅读导航：哪些问题在后面哪一篇展开。

**边界：**本篇回答“是什么、在哪里、有什么关系”。可以引用一个注明假设的容量结论，但详细推算放到第⑥篇。避免把“Attention 行为分类”直接等同于“完整 layer 结构分类”。

### ② Layer 0：基准层详解

保留现有 `02-layer0.md`，不改名、不从聊天重新生成另一份。

建议内部目录固定为：

1. **分析范围与符号**：层的输入输出、B*S 的含义、完整序列示例与带历史缓存场景的区别。
2. **整体八模块**：Attention 与 MoE 两个子层的先后关系、四路残差主线、系数与残差旁路。
3. **mHC**：混合系数生成 → 汇聚 `hc_pre` → 残差融合 `hc_post`；单独讲清 Single-Pass 的系数生成与使用位置。
4. **RMSNorm**：输入输出、归一化维度、公式、可学习权重与固定 epsilon。
5. **局部 Attention / SWA**：Q 支路、KV 支路；完整打分、mask、归一化、加权汇总；输出处理与投影。
6. **MoE FFN**：路由评分、专家选择、融合权重、专家内部函数、共享专家、输出合并。
7. **本层汇总**：输入输出、模块参数、需要保留的状态、与下一层的接口。

每个模块使用“**作用与位置 → 图 → 输入输出 → 公式与 shape → 易错点**”的基本顺序；不为套模板重复写空话。图已有的文字不逐字复述，但关键公式、维度和结论保留可检索文本。

**边界：**当前阶段讲数学逻辑。Attention 先保留完整序列维度，再通过 mask 表达限制；不提前用 gather、tile、物理分页或 GPU 调度取代数学解释。参数量可在本篇列明，实际字节数、计算量和性能权衡集中放到第⑥篇。

### ③ 其他层的差异：复用已讲清的知识

先列与基准层的对照表，再按有实质差异的类别展开。每类必须回答：

- 对应哪些层；与基准层哪些部分相同、可以跳过。
- 哪些模块新增、删除或改变；插入在完整流程的哪个位置。
- 输入输出、关键中间量与持久状态的 shape 有什么变化。
- 缓存和索引由哪层生成、哪层使用；共享的是数据、索引结果还是模型权重，不能混淆。
- 这些差异为什么存在，以及会给完整推理带来什么依赖。

**边界：**不是从 Layer 1 到最后一层逐层复述。特殊模块只在这里说明接入位置与接口，内部算法交给第④篇。必要时绘制一张完整流程并高亮新增部分，不能只孤立列出新模块名称。

### ④ 特殊模块详解：讲完整功能，不写成名词介绍

待用户逐项讨论后展开；目前候选主题是 Engram、视觉路径和 DSpark 等。每个模块按以下顺序：

1. 解决的问题与使用场景。
2. 在整个模型中的接入位置、上游和下游。
3. 输入输出、数学步骤、shape、参数或表结构。
4. 新增状态及生命周期。
5. 官方公开内容、尚未公开细节、本文推导或假设的区别。

**边界：**“特有”不等于所有位置都用，“代码含某模块”不等于完整生产调度已公开。内容过长时，由用户确认后拆成子篇，并通过目录页维护顺序；不要为维持六篇数量而硬塞。

### ⑤ 完整推理过程：从静态结构走到时间上的执行

建议分别走通三种情形：

- **Prefill**：处理一段输入时，各阶段先后做什么，哪些状态由此产生。
- **Decode**：单步生成时读取什么、新增什么，如何进入下一步。
- **多轮对话**：已有历史后再输入新消息，哪些状态可复用，哪些需要更新或重建。

统一跟踪本次 token、历史长度、层间隐藏状态、缓存、索引及辅助状态。先声明“完整保留状态”或具体服务端回收策略，再解释行为，避免混为一谈。

**边界：**重用前面各模块公式，不重新推导全部计算；主要讲依赖、时间顺序和状态生命周期。硬件上能否并行以及收益多少，转到第⑥篇。

### ⑥ 存储与计算分析：所有数字都能追溯假设

先固定计算口径：模型变体、B、S、S_his、数据类型、量化分组和 scale、是否跨卡切分，以及 MB／MiB 单位。

然后分开计算：

1. **参数与权重存储**：总参数、每 token 涉及的参数、量化与元数据开销。
2. **持久缓存**：全局、局部、索引和辅助状态，按共享关系去重。
3. **临时激活与工作区**：明确它们不等于全部需要同时长期保存的张量。
4. **计算量与访存量**：模块级计算，再汇总到层、阶段和整个模型。
5. **实现与硬件分析**：融合、稀疏访问、分页、并行切分及具体执行方案。
6. **交叉验证**：理论推导、参考实现分配量、推理引擎测量值分别列示并解释差异。

**边界：**缓存净数据量不等于进程显存；参数共享、缓存共享和索引复用分别计算。数学上存在一个完整张量，不代表实现必须将其完整物化。

## 5. 接手后的工作顺序

**当前任务仍是先上线已有内容，而不是完成六篇才上线。**

1. 阅读主交接文档，刷新远端状态，保留旧站备份与 Git 历史。
2. 将 `02-layer0.md`、九张原图和构建文件接入已有工作分支；按授权完成检查、合并与 Pages 部署。
3. 将本补充纳入 `progress/series-plan.md`，在系列目录页准确展示六篇规划及已有样章入口。
4. 交付实际可访问的 Pages、MD、九张图链接；不得以本地构建、创建 blob 或 CI artifact 代替上线。
5. 后续由用户选择继续画图、完善第②篇或开始新篇；每次更新正文、相关图注与维护状态，不擅自补写尚未讨论的章节。

本次补充本身不意味着已经更新 ZIP、远端仓库或站点；接手者需将此文件与原交接、原压缩包一起使用。
