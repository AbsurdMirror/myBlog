Layer 1：从 Engram 写入到局部注意力与 MoE

1. 相对 Layer 0，只看两处差异

本文分析 DeepSeek-V4.1-Flash 的 Layer 1。Layer 0 已经完整讲过 mHC、RMSNorm、局部 Attention / SWA 和 MoE；Layer 1 不再重复这些推导，而是回答两个新问题：

  1. Engram 怎样在普通 Transformer Block 之前，根据当前 token 及其局部历史检索条件记忆，并写回四路残差？
  2. Layer 1 的第一次 hc_pre 为什么不再使用固定的 [1,0,0,0][1,0,0,0]，而是使用 Layer 0 MoE 侧传来的动态 pre_next？

记

N=BS,D=5120,C=4,W=128. N=BS,\qquad D=5120,\qquad C=4,\qquad W=128.

Layer 1 从 Layer 0 接收：

Xin(1):[B,S,4,5120](BF16),pnext(0):[B,S,4](FP32). X^{(1)}_{\mathrm{in}}:[B,S,4,5120]\quad\text{(BF16)}, \qquad p^{(0)}_{\mathrm{next}}:[B,S,4]\quad\text{(FP32)}.

其中 Xin(1)X^{(1)}_{\mathrm{in}} 是四路残差，pnext(0)p^{(0)}_{\mathrm{next}} 是 Layer 0 的 MoE 侧 mHC 生成的下一次汇聚系数。完整数据流为：

(Xin(1),pnext(0))→Engram→Layer1Block→(Xout(1),pnext(1)) \boxed{ (X^{(1)}_{\mathrm{in}},p^{(0)}_{\mathrm{next}}) \rightarrow \mathrm{Engram} \rightarrow \mathrm{Layer\ 1\ Block} \rightarrow (X^{(1)}_{\mathrm{out}},p^{(1)}_{\mathrm{next}}) }

逐步对照如下。“结构相同”只表示算子、shape 和执行顺序与 Layer 0 相同；Layer 1 拥有自己的参数，输入数值也已经被 Engram 改变，并不与 Layer 0 共享权重或计算结果。

步骤 相对 Layer 0 Layer 1 的行为
1. Engram Hash、查表、门控与四路写回 新增 在普通 Block 前修改四路残差；不修改传入的 pre_next
2. Attention 侧 mHC 系数生成 结构相同 从 Engram 更新后的四路残差预测本层 attn_pre/post/comb
3. Attention 入口 hc_pre 输入不同 使用 Layer 0 MoE 侧生成的动态 pre_next，不再使用 identity-pre
4. Attention 入口 RMSNorm 结构相同 独立参数，输入来自步骤 3
5. Local Attention / SWA 结构相同 仍是 128-token 局部窗口，没有 compressed/global KV 或 Indexer
6. Attention 侧 hc_post 结构相同 融合 Attention 输出和 Engram 更新后的四路残差
7. MoE 侧 mHC 系数生成 结构相同 生成本层 ffn_pre/post/comb
8. MoE 入口 hc_pre 结构相同 使用本层 Attention 侧生成的 attn_pre
9. MoE 入口 RMSNorm 结构相同 独立参数
10. MoE FFN 结构相同 384 个 routed experts 选 6 个，并执行 1 个 shared expert
11. MoE 侧 hc_post 结构相同 输出四路残差，并把 ffn_pre 作为下一层的 pre_next

固定配置中 compress_ratios[1]=0，而 kv_source_layers 与 index_source_layers 都从 Layer 2 开始。因此 Layer 1 与 Layer 0 一样只执行 SWA；本页新增的注意力外路径只有 Engram。配置核查

2. Engram 在哪里，解决什么问题

Engram 把条件记忆作为 MoE 条件计算之外的另一条稀疏轴：MoE 根据隐藏状态选择少量专家进行动态计算；Engram 则根据确定性的局部 NN-gram 地址，从巨大表中只读取少量行。官方论文把这一过程概括为 Tokenizer Compression、Multi-Head Hashing、Context-aware Gating 和 Multi-branch Integration。Engram 论文

DeepSeek-V4.1-Flash 在零起始编号的 Layer 1 和 Layer 14 各放置一个 Engram。两者合计约 196B 逻辑参数；每个模块使用 NN-gram 阶数 {2,3,4}\{2,3,4\}、8 个 Hash head，每个阶数共 8×256=20488\times256=2048 维查表结果。Layer 1 的表有 384,006,168 行，每行 256 维。技术报告 §2.4.2

参考前向并不是进入 Layer 1 后才开始构造 Hash。Transformer.forward 会在进入层循环前，根据原始 input_ids 一次生成两个 Engram 层的 Hash：

Iall:[B,S,2,24](INT64). I_{\mathrm{all}}:[B,S,2,24]\quad\text{(INT64)}.

这里维度 2 对应 Layer 1 与 Layer 14，24=3×824=3\times8 对应三个 NN-gram 阶数和八个 Hash head。执行到 Layer 1 时，只取

I(1)=Iall[:,:,0,:]:[B,S,24]. I^{(1)}=I_{\mathrm{all}}[:,:,0,:]:[B,S,24].

因此需要把两个位置分清：

  • Transformer 级 Hash 前置组件：处理 Token 压缩、历史状态、两个 Engram 层的 Hash 与索引。
  • Layer 1 Engram 模块：读取本层的 24 个索引，执行查表、投影、门控和残差写回。

这也解释了为什么后面的显存分析不能把完整 Hash buffer 在 Layer 1 和 Layer 14 各算一遍。前向接入位置

3. 从 Token 到 24 个查表地址

3.1 Token 压缩与跨前向历史

原始 Token ID 为

T:[B,S],0≤Tb,t<129280. T:[B,S],\qquad 0\le T_{b,t}<129280.

Hash 前先通过固定映射 PP 把 129,280 个原始 Token ID 映射到 99,092 个压缩 ID：

T′b,t=P[Tb,t]. T'_{b,t}=P[T_{b,t}].

这张映射在模型构建时由 tokenizer 生成，会对可完整解码的 token 文本执行 Unicode 规范化、去音调、转小写、空白折叠和首尾空白处理；规范化结果相同的 token 共用压缩 ID。它是固定运行时 buffer，不是可学习参数。

Hash 组件还维护

Tcache:[Bmax,Smax](INT64), T_{\mathrm{cache}}:[B_{\max},S_{\max}]\quad\text{(INT64)},

所以 Decode 阶段可以读取 Prefill 或更早 Decode 已写入的最近三个压缩 Token ID，而不必重新处理全部历史。对于图像 span，压缩缓存写入特殊的 DEAD=-1；任何跨过 DEAD 的 NN-gram 都会被阻断并使用固定 pad_id 补齐。

令 ub,t,ru_{b,t,r} 表示位置 tt 向前回看 rr 步后的有效压缩 ID，r=0r=0 是当前 token：

ub,t,r={T′b,t−r,t−r≥0∧[t−r,t] 内没有无效 token,tpad,其他. u_{b,t,r}= \begin{cases} T'_{b,t-r}, & t-r\ge0\ \land\ [t-r,t]\text{ 内没有无效 token},\\ t_{\mathrm{pad}}, & \text{其他}. \end{cases}

3.2 乘法-XOR Hash 与互不重叠的分区

对 Engram 层 ℓ\ell，四个回看位置各有一个由层号确定的奇数乘数 μℓ,r\mu_{\ell,r}。2、3、4-gram 的滚动 Hash 为：

hb,t,n(ℓ)=⨁r=0n−1(ub,t,rμℓ,r),n∈{2,3,4}. h^{(\ell)}_{b,t,n} =\bigoplus_{r=0}^{n-1} \left(u_{b,t,r}\mu_{\ell,r}\right), \qquad n\in\{2,3,4\}.

每个阶数再进入八个不同的质数桶。记 Mℓ,n,qM_{\ell,n,q} 为模数、Oℓ,n,qO_{\ell,n,q} 为这段桶区间的起始 offset：

ib,t,n,q(ℓ)=Oℓ,n,q+(hb,t,n(ℓ)modMℓ,n,q),q=0,…,7. i^{(\ell)}_{b,t,n,q} =O_{\ell,n,q}+ \left(h^{(\ell)}_{b,t,n}\bmod M_{\ell,n,q}\right), \qquad q=0,\ldots,7.

三个阶数乘八个 head，得到每 token 24 个地址。每个 (n,q)(n,q) 使用不同质数大小和互不重叠的 offset，因此可以把它们理解为 24 张逻辑表；在参数存储上，它们拼成一张连续大表。

图中 G0G_0 表示当前 token，G1,G2,G3G_1,G_2,G_3 依次向历史回看；mask/pad/shift 还读取未单独画出的有效性 mask。正文公式是精确定义，图中的蓝色 $B\times S$ 块用于简写逐 token 的逻辑 shape。

Layer 1 的可学习表为：

Etable:[384006168,256]. E_{\mathrm{table}}:[384006168,256].

按 24 个地址读取：

Eb,t,n,q,:=Etable[ib,t,n,q(1),:],E:[B,S,3,8,256]. E_{b,t,n,q,:} =E_{\mathrm{table}}[i^{(1)}_{b,t,n,q},:], \qquad E:[B,S,3,8,256].

最后展平：

Eflat:[B,S,6144],6144=3×8×256. E_{\mathrm{flat}}:[B,S,6144], \qquad6144=3\times8\times256.

“每 token 读取 24 行”是逻辑查表口径。固定 reference 中 FP8 数据与对应 E8M0 scale 分别通过 F.embedding gather，因此它不能直接等同于底层访存指令数。Hash 实现

4.2 归一化匹配分数与 Signed Sqrt

先合并两套逐维缩放：

W=WQ⊙WK:[4,5120]. W=W_Q\odot W_K:[4,5120].

对于残差流 c∈{0,1,2,3}c\in\{0,1,2,3\}，分别沿 5120 维计算 RMS 倒数：

rb,t,cX=(15120∑d=05119Xb,t,c,d2+ϵ)−1/2, r^X_{b,t,c} =\left(\frac1{5120}\sum_{d=0}^{5119}X_{b,t,c,d}^2+\epsilon\right)^{-1/2},

rb,t,cK=(15120∑d=05119KE,b,t,c,d2+ϵ)−1/2,ϵ=10−20. r^K_{b,t,c} =\left(\frac1{5120}\sum_{d=0}^{5119}K_{E,b,t,c,d}^2+\epsilon\right)^{-1/2}, \qquad \epsilon=10^{-20}.

加权归一化点积为：

Db,t,c=rb,t,cXrb,t,cK5120∑d=05119Xb,t,c,dWc,dKE,b,t,c,d. D_{b,t,c} =\frac{r^X_{b,t,c}r^K_{b,t,c}}{\sqrt{5120}} \sum_{d=0}^{5119} X_{b,t,c,d}W_{c,d}K_{E,b,t,c,d}.

固定实现不会直接把 DD 送入 Sigmoid，而是先执行带符号平方根。这里使用 copysign 而不是简单的 sign(D)⋅\operatorname{sign}(D)\sqrt{\cdot}，从而与源码在 D=0D=0 时复制正号的边界行为一致：

D̃b,t,c=copysign(max(|Db,t,c|,10−6),Db,t,c). \widetilde D_{b,t,c} =\operatorname{copysign}\left( \sqrt{\max(|D_{b,t,c}|,10^{-6})}, D_{b,t,c} \right).

于是

gb,t,c=σ(D̃b,t,c). g_{b,t,c}=\sigma(\widetilde D_{b,t,c}).

多模态输入中的图像位置随后把 gate 置零；纯文本前向不需要 mask：

gb,t,c←{gb,t,c,Tmask,b,t=1,0,Tmask,b,t=0. g_{b,t,c}\leftarrow \begin{cases} g_{b,t,c},&T_{\mathrm{mask},b,t}=1,\\ 0,&T_{\mathrm{mask},b,t}=0. \end{cases}

图 2 把这两步合并画在 Sigmoid 附近；源码顺序是 先 Sigmoid，再用 mask 置零。

4.3 四路写回，但不改变 pre_next

最终输出为：

X′b,t,c,d=Xb,t,c,d+gb,t,cVE,b,t,d,X′:[B,S,4,5120]. \boxed{ X'_{b,t,c,d} =X_{b,t,c,d}+g_{b,t,c}V_{E,b,t,d} }, \qquad X':[B,S,4,5120].

这一步有三个容易混淆的点：

  1. VEV_E 在四路之间共享，不是从表中读取四份不同 Value。
  2. 四路 gate 独立，因此同一个 VEV_E 对四路的写入幅度不同。
  3. Engram 只返回更新后的四路残差 X′X'；Layer 0 传来的 pnext(0)p^{(0)}_{\mathrm{next}} 不经过 Engram，也不会被它重新计算。Engram 前向

5. Layer 1 第一次 hc_pre 的真正变化

模型只在最初把 embedding 扩成四路时创建一次 identity-pre：

pidentity=[1,0,0,0]. p^{\mathrm{identity}}=[1,0,0,0].

Layer 0 的 Attention 入口使用它；Layer 0 执行结束后返回 MoE 侧生成的 ffn_pre，即 pnext(0)p^{(0)}_{\mathrm{next}}。Layer 1 不会重新创建 identity-pre，而是直接用这个动态状态汇聚 Engram 更新后的四路残差：

Zb,t,d(1)=∑c=03pnext,b,t,c(0)X′b,t,c,d,Z(1):[B,S,5120]. \boxed{ Z^{(1)}_{b,t,d} =\sum_{c=0}^{3} p^{(0)}_{\mathrm{next},b,t,c} X'_{b,t,c,d} }, \qquad Z^{(1)}:[B,S,5120].

与此同时，Layer 1 Attention 侧的 hc_mixes 已经从 X′X' 预测出新的 attn_pre/post/comb。但这里的第一次 hc_pre 仍使用上一层传来的 pnext(0)p^{(0)}_{\mathrm{next}}；本层新生成的 attn_pre 留给紧随其后的 MoE 入口。顺序是：

pnext(0)⏟Layer 0 MoE 产生→Layer1Attentionhc_prepA(1)⏟Layer 1 Attention 产生→Layer1MoEhc_prepnext(1)⏟Layer 1 MoE 产生. \underbrace{p^{(0)}_{\mathrm{next}}}_{\text{Layer 0 MoE 产生}} \xrightarrow{\mathrm{Layer\ 1\ Attention\ hc\_pre}} \underbrace{p^{(1)}_{A}}_{\text{Layer 1 Attention 产生}} \xrightarrow{\mathrm{Layer\ 1\ MoE\ hc\_pre}} \underbrace{p^{(1)}_{\mathrm{next}}}_{\text{Layer 1 MoE 产生}}.

这正是 Single-Pass mHC 的跨子层、跨层系数传递。与 Layer 0 相比，Layer 1 的 hc_pre 算法没有变化，变化的是第一次调用的系数来源。Block.forward

6. 后续模块为什么不再展开

Engram 写回之后，Layer 1 进入与 Layer 0 同构的 Block。下面只记录复用关系；公式、shape 和内部步骤见 Layer 0：从四路残差到局部注意力与 MoE。

模块 Layer 1 相对 Layer 0 需要记住的差别
Attention 侧 mHC 算法与 shape 相同，参数独立 系数从 Engram 更新后的 X′X' 预测；首次汇聚用动态 pre_next
两个入口 RMSNorm 相同结构，参数独立 输入数值不同
Local Attention / SWA 相同结构，参数独立 同为 128-token 窗口；没有 global KV、Compressor 或 Indexer
Attention 侧 hc_post 相同 residual 是 Engram 更新后的四路张量
MoE 侧 mHC 相同结构，参数独立 其 ffn_pre 传给 Layer 2
MoE FFN 相同结构，参数独立 仍是 Top-6 routed + 1 shared expert
Local KV cache 与 RoPE 表 相同 shape，各层独立 不与 Layer 0 共用缓存或权重

所以 Layer 1 可以概括为：

Layer1=Layer0基准Block+前置Engram+动态跨层pre \boxed{ \mathrm{Layer\ 1} =\mathrm{Layer\ 0\ 基准\ Block} +\mathrm{前置\ Engram} +\mathrm{动态跨层\ pre} }

这里的加号表示结构差异，不表示参数共享。

25600×(6144mult+6143add)=314547200. 25600\times(6144\ \mathrm{mult}+6143\ \mathrm{add}) =314547200.

此外，参考实现每次 Engram 调用都会计算一次：

W=WQ⊙WK, W=W_Q\odot W_K,

产生 20,480 次逐元素乘法。若部署实现预先合并这两个只以乘积形式使用的静态权重，可省去这项。

所以处理 N=BSN=BS 个 token 时：

CEngram1,mul/add/sub=314731572N+20480 \boxed{ C_{\mathrm{Engram1,mul/add/sub}} =314731572N+20480 }

另有：

3NXOR,24N整数取模,25N逻辑Lookup, 3N\ \mathrm{XOR},\quad24N\ \mathrm{整数取模},\quad25N\ \mathrm{逻辑Lookup},

8Nrsqrt,4Nsqrt,4Nexp,4N除法,4Nclamp比较. 8N\ \mathrm{rsqrt},\quad4N\ \mathrm{sqrt},\quad4N\ \mathrm{exp}, \quad4N\ \mathrm{除法},\quad4N\ \mathrm{clamp比较}.

这里把 Sigmoid 按 1/(1+e−x)1/(1+e^{-x}) 展开计数；实际数值稳定 kernel 的指令数可能不同。Mask、边界检查、历史 gather 和布尔选择随输入情况变化，没有混入主公式。

完整 NgramHashState.forward 一次会同时计算 Layer 1 和 Layer 14，所以参考调用的 Hash 主体为每 token 8 次整数乘法、6 次 XOR、48 次取模和 48 次 offset 加法，但 Token 压缩映射仍只做一次。本文把其中一半 Hash 主体归因给 Layer 1；分析 Layer 14 时不能再次计入共享 Token 映射和缓存。

8.3 Layer 1 整层计算量

Layer 0 的官方通用路径为：

CLayer0=N(755138906+131200L¯), C_{\mathrm{Layer0}} =N\left(755138906+131200\overline L\right),

其中 L¯\overline L 是每个查询实际参与 SWA 评分的平均局部历史长度，1≤L¯≤1281\le\overline L\le128。Layer 1 后半段使用同一通用路径；它的首次 hc_pre 是动态系数，不能做 Layer 0 identity-pre 的理论常量折叠。

加上 Engram：

CLayer1,mul/add/sub=N(1069870478+131200L¯)+20480 \boxed{ C_{\mathrm{Layer1,mul/add/sub}} =N\left(1069870478+131200\overline L\right)+20480 }

在暂不考虑 L¯\overline L 的固定部分时，Engram 使本层每 token 的加/减/乘主项比 Layer 0 reference 增加约 41.68%。这个比例不是实际延迟比例：Engram 表可预取和分片，FP8 GEMM、访存、通信、并发重叠与 kernel 融合都会改变硬件时间。官方报告的 Engram 预取说明

9. Required Global Memory 理论下界与状态

这一节给出固定 reference 的共享状态视角：参数和 scale、层边界 I/O、本层 local Attention 状态、模型级 Hash 固定 buffer、Token 历史 cache，以及同时服务 Layer 1 和 Layer 14 的完整 engram_hashes。内部 Eflat,F,KE,VE,D,gE_{\mathrm{flat}},F,K_E,V_E,D,g 假设可通过融合、分块或工作区复用，不要求全部同时写入 Global Memory。

9.1 边界 I/O 与持久状态

Layer 1 输入和输出均包含四路 BF16 残差与一份 FP32 pre：

Mboundary=2×N(4×5120×2+4×4)=81952NByte. M_{\mathrm{boundary}} =2\times N(4\times5120\times2+4\times4) =81952N\ \mathrm{Byte}.

本层 Attention 状态与 Layer 0 相同：

window_kv_cache:[Bmax,128,512]BF16=131072BmaxByte, \mathrm{window\_kv\_cache}:[B_{\max},128,512]\ \mathrm{BF16} =131072B_{\max}\ \mathrm{Byte},

freqs_cis:[Smax,32]Complex64=256SmaxByte. \mathrm{freqs\_cis}:[S_{\max},32]\ \mathrm{Complex64} =256S_{\max}\ \mathrm{Byte}.

模型级 Hash 前置组件持有：

9.2 汇总公式

纯文本路径没有 engram_mask，于是：

MLayer1,min=108958172824+81952N+384N+131072Bmax+256Smax+1035072+8BmaxSmaxByte \boxed{ \begin{aligned} M_{\mathrm{Layer1,min}}={}&108958172824 +81952N +384N\\ &+131072B_{\max} +256S_{\max}\\ &+1035072 +8B_{\max}S_{\max} \end{aligned} \quad\mathrm{Byte} }

整理为：

MLayer1,min=108959207896+82336N+131072Bmax+256Smax+8BmaxSmaxByte \boxed{ M_{\mathrm{Layer1,min}} =108959207896 +82336N +131072B_{\max} +256S_{\max} +8B_{\max}S_{\max} \quad\mathrm{Byte} }

多模态路径若把新生成的 BOOL engram_mask:[B,S] 独立计入，再加 NN Byte。上式把整份 Hash 固定 buffer、Token cache 和 [B,S,2,24] Hash 输出计了一次；它们是 Layer 1 与 Layer 14 共享的模型级资源，做整模型汇总时不能再次相加。

这仍不是进程峰值显存，也不是显存读写量：未融合激活、FP8 解量化临时值、GEMM workspace、allocator 保留区、分片通信 buffer 以及实际推理引擎的 Engram CPU / host-memory offload 都会改变测量结果。

10. Layer 1 的跨层输出与结论

Layer 1 最终输出：

对象 Shape dtype 去向 / 生命周期
四路残差 Xout(1)X^{(1)}_{\mathrm{out}} [B,S,4,5120] BF16 Layer 2 Attention 侧 mHC
pnext(1)p^{(1)}_{\mathrm{next}} [B,S,4] FP32 Layer 2 第一次 hc_pre
window_kv_cache [B_max,128,512] BF16 Layer 1 后续 Decode 的 128-token 环形窗口
Token Hash cache [B_max,S_max] INT64 Layer 1、14 共用的跨 Prefill / Decode 压缩 Token 历史
engram_hashes [B,S,2,24] INT64 本次前向中供 Layer 1、14 依次消费

核心结论只有三条：

  1. Layer 1 是 Layer 0 基准 Block 的第一次结构扩展。 新增 Engram，但 Attention 仍是纯 128-token SWA，MoE 与 mHC 主体不变。
  2. Engram 向四路写入共享 Value、独立 Gate。 它更新四路残差，却不改动 Layer 0 传来的动态 pre_next。
  3. 本层容量主要由条件记忆决定。 单个 Engram 带来 98.463B 逻辑参数和约 94.562 GiB 的 world_size=1 参考权重驻留；实际部署依赖行分片、预取或 host-memory offload，而不是把它理解成必须单卡常驻的普通线性层。
